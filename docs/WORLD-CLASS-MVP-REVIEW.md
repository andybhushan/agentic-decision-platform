# ADP World-Class MVP: deep review + wave plan

**Date:** 2026-07-12 · **Owner:** Anand (DT Offering) · **Goal:** an MVP that impresses customers and IBM leadership: world-class UI/UX on Microsoft's latest agentic stack (IQ series and friends).

## 1. Evidence-based audit (what is real today)

Verified against live `ca-tracesapi`, the deployed console, the Fabric workspace, and code.

| Layer | Current state | Verdict |
|---|---|---|
| **Experience** | Platform console (queue, lifecycle Decision Mode, live SignalR trace, HITL, governed actions, Carbon Charts outcomes, narrator) + two client-branded portals (Meridian claims, Northwind lending), dark/light, deployed on SWA with shared-link gate | Strong; explainability data was underexposed (fixed in Wave 1) |
| **Agent runtime** | `AGENT_BACKEND=legacy` = direct Azure OpenAI (gpt-4o) chat completions. `FoundryAdapter` exists but unused (`FOUNDRY_PROJECT_ENDPOINT` not set) | **Gap: not on Foundry Agent Service / Agent Framework** (Wave 2) |
| **Foundry IQ (knowledge)** | AI Search `adp-knowledge`, 19 governed docs WITH ontologyBindings + regulatoryBasis front-matter, hybrid retrieval, cited per step | Real and live; citations lost fidelity through Cosmos (fixed: v1.2 `citedSourcesFull`) |
| **Fabric IQ (semantic)** | Runtime: 3 generic SQL primitives (entity history, similar-by-attributes, secondary history) over the lakehouse via schemaBinding, cited as `FabricIQ`. Workspace also has the REAL Fabric IQ items: Ontology `claims_ontology` (23 entities), GraphModel, SemanticModel, Data Agent `claims_data_agent`; none are called by the runtime | **Gap: ontology/graph/data agent adjacent to the loop, not in it** (Wave 3) |
| **Work IQ (collaboration)** | `WorkIqSource` (simulated Teams threads, cited as `TEAMS_THREAD/...`) live for claims; `MicrosoftGraphWorkIqSource` (real Graph) exists but not wired | Honest simulation; real Graph is Wave 4 |
| **Journal / explainability** | Per-step ontology entities, regulatory paragraphs, and federated citations ARE in the live journal (verified on settlement trace) | Was invisible in UI (fixed in Wave 1) |
| **Governance** | Immutable journal, HITL gates (organic, both industries), operator actions journaled, decision record artifact (Wave 1). Agent 365 registry: local stub. Entra Agent ID: declared, not enforced | Registry/identity UI story = Wave 4 |
| **Backend hygiene** | Anonymous API (demo), CORS scoped, SignalR live, intake durable, boundary check green | Adequate for demo; auth hardening deferred deliberately |

Key finding: **the journal already carries the full Microsoft IQ federation story** (FoundryIQ + FabricIQ + WorkIQ citations, `acl:*` ontology entities, NAIC/CCR regulatory paragraphs per step). The fastest world-class win was surfacing it, then upgrading the runtime underneath.

(c) Microsoft Agent Framework in-process runtime: viable and **SHIPPED, now the ACTIVE cloud runtime** (2026-07-12): **`AgentFrameworkAdapter`** (`Microsoft.Agents.AI.OpenAI` 1.13.0, `ChatClientAgent` over the key-authenticated `AzureOpenAIClient`, MCP tools bridged as `AIFunction` subclasses journaling every call, shared `PromptContract` so decision semantics are identical across all three backends). - **Wave 5: polish + demo curation. STATUS 2026-07-12: SHIPPED.**
  Done: **per-use-case lens on Outcomes** (`?packages=` filter on /aggregate/outcomes + /aggregate/timeline, image `v11-lens-b`; console Dropdown scopes KPIs + both charts to claims or lending); **narrator rewritten to 8 beats** covering the full arc (client brief → platform+portals → member front door → lifecycle run → IQ-federation grounding → HITL → outcomes lens → Agents page + Decision Record close); **`scripts/demo-warmup.mjs`** (pre-demo: runs claims across stages + a banking application and leaves one claim at an open gate so the queue shows a live "needs review" row).
  Build-pipeline lesson (cost one bad deploy, caught by verification): grep-filtered `dotnet publish` output masks a failing exit code (TreatWarningsAsErrors), letting a stale publish ship: v11 first went out with old binaries. Always gate the ACR build on the publish exit code, and verify behavior after every deploy.

- **Wave 6: damage-photo evidence + vision at intake. STATUS 2026-07-12: SHIPPED (image `v13-evidence-3`).**
  Members now upload real damage photos in the claim wizard (canvas-resized to 1024px JPEG client-side, up to 6, previews + remove). Storage: blob container `evidence` on the platform storage account, layout `{groupId}/photo-N.jpg` plus alias blob `subjects/{subjectId}`; endpoints `POST /api/evidence`, `GET /api/evidence/subject/{id}`, `GET /api/evidence/file/{groupId}/{name}` (Functions/Evidence.cs, EvidenceStore in ContextLayer). **Vision runs once at intake** (PostIntake): GPT-4o describes the photos objectively and the description is embedded into the stored record as `evidenceAssessment` (+ `evidencePhotoCount`), so every stage's agents receive it inside the claim JSON with zero per-run cost; failures degrade gracefully. Surfaces: member tracker gets a "Damage assessment" card (photos, "what our AI saw", repair-estimate figure lifted from the Damage & Estimation step output); Decision Mode gets a "Submitted evidence" side card (thumbnails + the intake vision assessment). E2E verified live: upload → intake CLM-2026-10028 → assessment on the record → tracker card renders on the SWA.
  **SDK trap (cost two deploys):** `Azure.AI.OpenAI` 2.1.0 chat completions throw `MissingMethodException` (`ChatCompletionOptions.get_SerializedAdditionalRawData`) when the process resolves `OpenAI` 2.10.0 (pulled by `Microsoft.Agents.AI.OpenAI` 1.13.0): `AzureChatClient.PostfixSwapMaxTokens` is binary-incompatible, and no newer stable Azure.AI.OpenAI exists. Fix: EvidenceVision calls the Azure OpenAI REST API directly over HttpClient (`api-version=2024-10-21`, `api-key` header, base64 `data:` URLs). Any new direct chat-completions code in this platform must do the same (the agent adapters are unaffected because they never construct `ChatCompletionOptions` this way).
